## Research and how it applies

- **Compose performance:** Android’s [Compose performance best practices](https://developer.android.com/develop/ui/compose/performance/bestpractices) recommend stable lazy keys, keeping rapidly changing state out of broad UI and moving expensive work away from composition. Sundown uses stable keys, precomputes grouping/sorting/search indexes on background dispatchers, keeps playhead state in the timeline, and prefetches only a short window of visible artwork. No extra image/network dependency was added.
- **Artwork:** The existing local `ArtworkStore` was retained instead of copying an image stack. Its bounded LRU, I/O decoding, in-flight coalescing and cancellation patterns were compared with [LocalTracklist’s artwork loader](https://github.com/quietswitch/LocalTracklist/blob/master/app/src/main/java/com/libreplayer/ui/components/Artwork.kt). Sundown additionally uses bounded Rust previews and avoids the platform getter that allocates the full embedded-picture blob before a size check.
- **MediaStore:** Android’s [shared-media guide](https://developer.android.com/training/data-storage/shared/media) documents per-volume discovery, version/generation checks and the aggregate external collection. That maps to Sundown’s per-volume watermarks and conservative detach handling: after scanning, only volumes still mounted can contribute changed rows, current IDs or deletion authority. The legacy aggregate cannot safely distinguish missing-card data, so it is not treated as deletion proof.
- **Permissions:** Android’s [granular media permissions](https://developer.android.com/about/versions/13/behavior-changes-13) support audio-only access: `READ_MEDIA_AUDIO` on API 33+ and the legacy audio read permission on older supported versions. Android’s [notification runtime-permission guide](https://developer.android.com/develop/ui/compose/notifications/notification-permission) explicitly exempts media-session notifications, so Sundown uses Media3’s session notification without an unnecessary `POST_NOTIFICATIONS` prompt.
- **Playback:** Android’s [Media3 background-playback guide](https://developer.android.com/media/media3/session/background-playback) and the [Media3 session demo](https://github.com/androidx/media/tree/release/demos/session) put the Player/MediaSession in a service and derive notification state from the session. Sundown follows that design and supplies local artwork metadata; it does not hand-roll a notification or use Notification Listener Access. The guide’s paused-service/resumption lifecycle remains a device validation item, not a claimed feature.
- **Back and edge-to-edge:** Android’s [predictive Back guide](https://developer.android.com/develop/ui/compose/system/predictive-back) and [Compose inset guidance](https://developer.android.com/develop/ui/compose/system/insets) support gesture-progress handling and separating drawing, content and gesture insets. Sundown scopes Back to the active modal/sheet/filter and applies status/cutout/navigation/IME insets locally; actual gesture-bar behavior still needs device testing.
- **Open-source Android player comparisons:** [Auxio’s MediaStore layer](https://github.com/OxygenCobalt/Auxio/blob/dev/musikr/src/main/java/org/oxycblt/musikr/fs/mediastore/MediaStore.kt) informed per-volume source review; Auxio’s inspected session holder uses `MediaSessionCompat`, so it was not copied as a Media3 template. [LocalTracklist’s device scanner](https://github.com/quietswitch/LocalTracklist/blob/master/app/src/main/java/com/libreplayer/library/scanner/DeviceLibraryScanner.kt) informed post-scan volume-stability checks; its [playback service](https://github.com/quietswitch/LocalTracklist/blob/master/app/src/main/java/com/libreplayer/media/service/PlaybackService.kt) was a native service comparison. No third-party implementation was copied and no dependency was added.
